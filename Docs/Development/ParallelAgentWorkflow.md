# 五项需求的并行 Agent 开发约定

制定日期：2026-11-12。适用范围：本轮五项需求及其集成；完成后保留作交接依据，不自动扩大为永久目录所有权。

所有参与者先读根目录 `AGENTS.md`、`Docs/DevelopmentGuidelines.md` 和本文，再读自己与对方的交接记录。用户后续指令优先；本文只规定协作方式，不代表五项功能已经实现，也不代替待确认的策划、美术和具体数值。

## 1. 分工

- **A 组：交给其他人/其他 agent。**需求 1：新增涉及真实硬件输入的教程界面；需求 2：关卡内 UI 替换。负责页面、美术、布局、UI 数据展示、教程进度和 UI 导航。
- **B 组：用户所在开发线/当前关卡 agent。**需求 3：关卡开场动画和中场动画；需求 4：调整上下轨时长，开头及结束回到中轨；需求 5：跟随千纸鹤的箭头。负责关卡流程、路线、玩家与镜头表现及关卡接线。
- 本文不授权自动启动其他 agent。收到具体开发任务的 agent 只负责对应组；职责不明时先做只读检查，再确认角色，不能默认为同时接管两组。

## 2. 文件归属：同一文件只有一个写入方

### A 组写入范围

- `Assets/Scripts/UI/`：教程、HUD、页面路由、运行时 UI 绑定；包含 `Runtime/BreathUIFlowController.cs`、`Runtime/UIFlowBindings.cs`、`Navigation/UIScreenId.cs` 和 `Legacy/BreathHud.cs`。
- `Assets/Prefabs/UI/`：包含 `UIFlowRoot.prefab`、页面和共用 UI 组件；`Assets/Art/UI/` 内本次新增或明确替换的 UI 素材。
- `Assets/Editor/UI/` 内 UI 专用工具、UI 验证；`Assets/Scenes/UI/UIFlowPreview.unity` 的 UI 预览。预览场景不加入正式关卡切换流程。
- 教程相关文档、自己的交接记录 `Docs/Handoffs/ParallelUI.md`。

### B 组写入范围

- `Assets/Scripts/Levels/`、`Assets/Scripts/Gameplay/`：关卡管理、会话/路线、玩家、镜头、纸鹤和箭头表现、收集物/避让提示的适配。
- `Assets/Prefabs/Levels/`、`Assets/Settings/Levels/`；本次关卡动画、箭头使用的新素材/Timeline 资源放在职责清晰的独立目录。
- `Assets/Scenes/BreathDemo.unity`：**B 组是主场景唯一接线方**。A 交付 UI Prefab 和接线说明，B 集成；保留嵌套 Prefab 引用，不通过 Unpack 或整份场景替换完成接线。
- `Assets/Editor/Setup/`、`Assets/Editor/Validation/` 中与本次关卡有关的工具和验证；关卡文档、自己的交接记录 `Docs/Handoffs/ParallelGameplay.md`。

### 公共文件的处理

- `BreathUIFlowController.cs` 虽关联游戏流程，仍归 **A**；`BreathLevelManager.cs` 与 `BreathSession.cs` 归 **B**。另一组需要改变时，在自己的交接记录写明需求，由所有者实现。
- `Assets/Scripts/Input/`、`Assets/Settings/Input/`、固件、第三方插件、包、程序集定义、URP 和 ProjectSettings 默认只读。本轮教程不自行修改蓝牙协议、阈值、设备标识或连接生命周期。确有必要时先由两组明确唯一执行方和范围。
- `AGENTS.md`、开发指南、本文由 B 维护；A 提出修订请求。未列出的既有共享文件，先明确归属，再写入。
- 每个资源的 `.meta` 与资源本体归同一方；保留既有 GUID，不以删除再建或复制别人的 `.meta` 解决冲突。
- **归属限制同样适用于间接改动。**运行生成器、批量 setup、美术应用菜单、自动保存场景之前，先看它会写哪些文件；会覆盖对方文件时改成定向操作或交给所有者执行。历史 setup 可能重置 UI、镜头和关卡参数，不能直接整批重建。

## 3. 对接边界

### 已有接口：可以作为当前基线

- 硬件统一复用已有 `ArduinoBreathInput`（名称保留，当前默认支持 BLE）、`ReceiverSnapshot`、`ThresholdsValid`、`DecisionLabel` 和现有配置，参考 `Docs/Hardware/BluetoothInput.md`、`Docs/Hardware/HardwareSettings.md`。
- `ReadLane()` 在断连时可能回退到键盘。真实硬件教程的通过条件必须同时确认新鲜硬件样本和有效阈值，不能仅凭 W/S 或 `ReadLane()` 通过“硬件已掌握”的步骤。键盘练习若保留，要明确区分模式。
- 现有导航已包含 `PracticeInhale`、`PracticeExhale`、`PracticeFollow`、`PracticeComplete` 以及练习逻辑；A 先评估复用/扩展，避免再造一套冲突的教程流程。
- UI 发出开始、暂停、继续、重开、退出请求；正式关卡由 `BreathLevelManager` 统一处理。UI 读取会话/展示状态，不直接改写路线时间、玩家位置、纸鹤位置或关卡根对象激活状态。

### 本轮待实现的对接契约

以下是两组实现时需要兑现的语义，**不是已经存在的 C# 类型或方法**。B 在自己的交接记录发布实际接口名称、路径和用法，A 在自己的记录确认采用；不能一边假定接口已存在，一边提交无法编译的引用。

- B 提供可读取的阶段状态，至少能区分开场、正式游玩、中场、收尾回中轨和已完成，并说明进入/退出通知及初次绑定时如何读取当前状态。
- B 说明各阶段是否接受呼吸控制、是否推进路线/关卡计时、是否生成和收集星星、HUD 应读取哪个时间及进度。UI 不自行从秒数推算当前阶段。
- A 保持教程自身进度独立；开始正式关卡的请求只发送一次。教程通过不直接推进正式关卡时钟，也不保存成一次正式关卡成绩。
- 结束回中轨和收尾动画必须完成后，A 才显示结算并记成绩。当前 UI 会观察 `BreathPhase.Finished`；若 B 改动其含义，必须先通知 A 适配完成判据，避免收尾被现有 `Finish()` 提前中断。
- 暂停入口由 A 的 UI 流程协调，B 的关卡/动画响应统一暂停状态；两组不各自持有一套 `Time.timeScale` 恢复值。教程期间仍保持硬件接收，界面退出时解除订阅，不把共享接收器关闭。
- 箭头属于 B 的关卡表现，跟随真实纸鹤 Transform；A 不在 HUD 内另建第二套跟随逻辑。需要 UI 图层时，A 提供挂载点，B 提供独立箭头 Prefab/控制器，由 B 在主场景接线。
- 上下轨时长、开场/中场长度、回中轨方式、教程通过时长、UI 视觉和箭头样式尚需具体需求；两组分别记录待确认项。可先实现可配置部分，不把临时数值写成用户已确认的规则。

B 应优先公布阶段/暂停/结束的接口方案；A 可先并行制作页面、教程输入验证及独立 UI 预览，不必等待关卡动画完成。暂时模拟的数据只用于开发预览，正式交付必须接真实状态，并注明尚未接入部分。

## 4. 同一目录、编辑器和 MCP 的使用

- 共享同一工作目录时，文件改动立即互相可见。分支名不能隔离同一目录；不要在另一组工作时 checkout、reset、stash、clean 或回滚整个项目。提交时只暂存自己的明确文件，不用 `git add .`。
- 默认复用当前编辑器/Library。**同一个 Unity 编辑器及其 MCP、本地请求桥接队列同时只允许一组操作**，包括 Play/Stop、切预览场景、Prefab Stage、导入、setup、截图和测试。
- B 是默认编辑器协调方。A 需要验证时，在 `ParallelUI.md` 登记请求；B 执行，或在 `ParallelGameplay.md` 明确释放，再由 A 接手。A 完成后在自己的记录释放并说明当前场景、Play 状态和待保存项。
- 开始前同时查看两份记录；状态不清楚先通过双方聊天/任务消息交接，不能把“暂时没回复”当作允许抢占。文档记录不是原子锁，出现同时申请时由 B 协调先后。
- 编辑器被占用期间，另一组可继续编写自己拥有的源文件和准备素材，但要先告知保存批次，避免自动刷新中断对方的 Play/测试；需要稳定验证时约定短暂冻结保存。不要禁用域重载或反复强制编译规避协调。
- 本次文档建立不代表任何一组已经占用编辑器。实际操作者必须在自己的交接记录写明当前占用/释放状态。
- 只有确实需要隔离验证时才协调独立 worktree 和独立 Unity 实例；不共用 Library，不把每轮新建无缓存项目作为默认流程。隔离后的资源/GUID、公共接口及主场景仍按本文件分工整合。

## 5. 交付与集成顺序

1. 两组各自记录改动前状态，保留已有修改；在各自交接文件登记本次负责文件、接口需求和编辑器请求。超出归属的文件先交接，不直接抢改。
2. B 发布最小阶段接口及时间语义；A 对接并记录确认。接口变更时保留可用过渡或一起完成调用方适配，不让主工作区长期无法编译。
3. A 交付教程/HUD Prefab、依赖、需挂载的组件和序列化绑定路径，以及其 UI 流程改动；B 交付动画/路线/箭头和状态接口。交接文件列出实际修改文件、验证证据、未完成项。
4. B 在主场景定向接入双方已交付资源；遇到 UI Prefab/脚本问题退回 A 修改，不用覆盖 A 文件应急修复。A 如需修改 B 文件也按同样方式办理。
5. 复用现有编辑器，批量保存后等待增量编译并检查控制台；只按实际变更定向导入。纯文档修改不触发 Unity 编译。
6. 联调通过后，两组各自在自己的记录标记已集成；不能把仅有截图、模拟输入或编译通过写成真实硬件验收完成。

最低联调范围：硬件新鲜输入/断连/重新连接、吸气/呼气/无输入、教程重进及键盘模式隔离；HUD 的时间/分数/暂停按钮；开场与游玩无停顿衔接、中场暂停恢复、结尾回中轨后才结算；路线/纸鹤/星星/避让提示共享正确时间；箭头跟随与出镜处理；两关切换、重开、退出后的事件/Timeline/补间清理。同一主场景正常游玩恰好一个关卡激活。

## 6. 给其他 Agent 的入口

转交 A 组时告知：“你负责需求 1/2。先读 `AGENTS.md`、`Docs/DevelopmentGuidelines.md`、`Docs/Development/ParallelAgentWorkflow.md` 和两份 Parallel 交接记录，按 A 组边界工作；主场景由 B 接线。当前只授权具体交给你的功能，不自行接管 3/4/5。”

转交 B 组时告知：“你负责需求 3/4/5 和主场景集成。先读上述约定及两份交接记录，优先公布阶段接口；不要修改 A 组教程/UI 文件，通过交接请求其所有者适配。”
