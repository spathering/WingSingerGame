# 循环与中场视频的云朵转场

使用用户提供的「透明背景_1080」目录中的 152 帧 RGBA PNG，按原顺序在第 1 关两处播放：循环 1 → 中场视频、中场视频 → 循环 2。原图复制到 `Assets/Art/LevelSequences/CloudTransition/`，不修改用户素材；Windows 导入使用 BC7、2048 上限、不生成 mipmap、不保留 CPU 可读副本，保留透明通道。

默认 30 fps，单次约 5.07 秒；`CloudTransitionOverlay` 的帧率和切换帧可配置。复用现有 UI 帧混合 Shader 插值相邻帧。独立 Overlay Canvas 排序 600，位于中场视频（500）和游戏 HUD 上方，等比覆盖屏幕。素材在第 96 帧附近最密，但仍有约 2.3% 透明缝隙，因此只在切换点前后平滑加入云色底层，遮满后切换，散开时撤去。

## 时间与生命周期

- 循环 1 到 50 秒时停止路线与收集，先播放云朵。在第 96 帧启动中场视频解码并暂停在首帧，等云朵散开后才正式播放，因此不会跳过视频开头。
- 中场完整播放结束后，再播放一次云朵，遮满时隐藏中场并启动循环 2；云朵继续散开，循环 2 的中轨准备段在其下连续前进。没有额外循环时间或提前生成下一段星星。
- 云朵动画取代这两处的视频画面淡入 / 淡出，避免散开后再次透明闪烁；中场音频仍保留原有渐入 / 渐出。开场视频静音保持不变。
- 暂停冻结云朵和路线，临时隐藏转场覆盖层以露出暂停菜单；继续时恢复同一帧。关卡退出、重开、切关均停止并清空覆盖层。
- 新阶段 `CloudToIntermission` / `CloudToGameplayTwo` 追加在既有枚举后，保留原编号；第 2 关不绑定此组件。未配置素材时保留原淡入 / 淡出逻辑。

## 中场单次播放修正（2026-11-17）

上述 35 类结果为云朵初次接入时的历史验收。本轮针对中场疑似循环，移除了“播放器没有播放就再次 Play”的逐帧重试：中场正式播放只启动一次，继续播放只由明确的暂停恢复触发。首帧预览继续在云层下暂停。原生循环开关显式关闭；结束回调与最后一帧的解码回调均可标记完成，下一次 Tick 进入第二次云朵转场。重开清空单次启动和结束标记，关卡退出后忽略旧回调。

当前验证分为两种，不能混同：

- `validate-playback-state`：使用真实关卡控制器和模拟解码事件，15 项检查通过，覆盖末帧兜底、延迟 / 过早结束回调、停止时不自动重播、显式暂停恢复、两次转场、重开和退出清理。报告为 `Docs/Validation/IntermissionPlaybackState.txt`。
- `validate` / `validate-full`：保留完整原生视频播放检查，并模拟丢失中场 EOF 回调，要求视频时间单调前进且在一个片长内退出。本轮未通过：当前编辑器的原生播放器停在第 0 帧，独立无游戏回调的播放器也无法推进；重开已保存编辑器后仍复现。当前失败记录为 `Docs/Validation/FirstFlightSequence.txt`。因此本轮不能声称完整约 52 秒视频实播已验收。

没有清除 Library、改视频编码、变更硬件或重建场景。开场静音和原有 UI 配置保留。
