# 动画插值与前景白边（2026-11-03）

## 流畅度

前景与 UI 现在在当前帧和下一帧之间按每个实际渲染帧插值，不再只以 20 FPS 切换整张图。在画面实际运行 60 FPS 时会每秒更新约 60 个混合状态，120 FPS 时同样跟随刷新；此功能本身不保证设备渲染帧率，也不把原始素材描述为原生 60 FPS 动作。

时间轴不加速：前景仍为 150 源帧、7.5 秒一轮，UI 为 100 帧、5 秒一轮。循环末帧和首帧也参与插值。没有扩大为 450 张前景纹理或再放大 UI 图集，额外 GPU 成本是多采样一次纹理；暂停、重开、关闭复位继续沿用已有生命周期。

`LoopingPanorama` 给现有 URP Shader 传入下一张纹理和小数帧权重；静态背景的权重默认为零。`UISpriteAnimation` 使用专用 uGUI Shader，同时映射两个 Sprite 的图集矩形，单独管理各页面材质，页面关闭时释放。Shader 放在 Resources 中保证构建保留。颜色以预乘 Alpha 混合，避免两层 Image 叠加导致透明度变浅；主角动作和呼吸判断的时序未改变。

## 白边来源与修复

对原始 `合成 1_00000.png` 的像素检查发现：2,310,195 个 Alpha 位于 11–244 的边缘像素中，1,400,219 个 RGB 三通道均超过 210。白色污染已存在于源序列，缩小、放大显示和纹理过滤会让它更明显；不是只靠提高动画帧率就能修复的问题。

`Tools/repair_foreground_edges.py` 在导入副本上修复半透明、偏白且近中性的边缘 RGB，用附近不透明内容的颜色扩展填充，保留原 Alpha 与不透明像素。只处理八像素以内可找到可靠颜色的边缘，避免误改树木内部的亮色细节。全部 150 帧累计处理 6,456,989 个像素；原始 6 GB 素材不改动。原转换脚本也接入相同处理，Manifest 使用版本标记防止重复处理。

修复后 PNG 合计 224,065,763 字节，仍比原序列少约 96.35%；纹理尺寸、BC7、150 张常驻数量保持。实际效果见 `Docs/Images/AnimatedForeground.png`，验证结果见 `Docs/Validation/AnimatedForeground.txt` 和 `Docs/Validation/NovemberArt.txt`。
